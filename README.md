# DSH 插件：Siri 语音桥

把 iPhone 的「快捷指令 + Siri」接进 DSH：手机上按住说话，话进到电脑上的会话里；回复再由快捷指令取回来。

**只依赖 DSH 自带的东西**：不需要 QQ 桥、不需要 `@dsh-mobile/mobile-remote`、不需要额外 `npm install`。

---

## 一、安装

### 方式 A：npm（最省事）

已经发到 npm 公共源了：

```bash
dsh plugin add dsh-siri-bridge
```

或者在 DSH 侧边栏的**插件页**里，输入框里填 `dsh-siri-bridge` 回车。

装完重启 DSH，进「设置 → 插件 → Siri 语音桥」。

版本：https://www.npmjs.com/package/dsh-siri-bridge

### 方式 B：直接拿文件夹（离线备用）

1. 把整个 `dsh-siri-bridge` 文件夹放进下面任意一处：
   - `~/.dsh/plugins/dsh-siri-bridge`（推荐，跟着 DSH 走）
   - 或者你自己的工作区里，比如 `<工作区>/plugins/dsh-siri-bridge`
2. 打开 `~/.dsh/profiles/<你的profile>/package.json`（一般是 `~/.dsh/profiles/desktop/package.json`），做两处改动：

```jsonc
{
  "dependencies": {
    "dsh-siri-bridge": "link:C:/Users/你/.dsh/plugins/dsh-siri-bridge"
  },
  "dsh": {
    "bundles": [ "……", "dsh-siri-bridge" ]
  }
}
```

3. 重启 DSH。
4. 进「设置 → 插件 → **Siri 语音桥**」就能看到页面。

> 注意：写 JSON 一定要存成**无 BOM 的 UTF-8**。带 BOM 会让 DSH 启动直接报 `cannot parse profile manifest`。
> 用记事本「另存为 → UTF-8」通常没问题；用 PowerShell 拼中文容易乱码，尽量别用。

> 用 `link:` 之前，`~/.dsh/profiles/<profile>/node_modules/dsh-siri-bridge` 那个位置得有个指向插件文件夹的 junction（或者干脆把插件文件夹直接拷进去）。
> Windows 下用管理员 cmd 跑：`mklink /J "%USERPROFILE%\.dsh\profiles\desktop\node_modules\dsh-siri-bridge" "%USERPROFILE%\.dsh\plugins\dsh-siri-bridge"`。
> 没有这一步，DSH 启动会报 `cannot resolve profile bundle "dsh-siri-bridge"`。

### 方式 C：把 zip 给别人

对方拿到的是压缩包，解压后最省事的就是按方式 B 走：

1. 解压，把里面的 `dsh-siri-bridge` 文件夹整个挪到 `%USERPROFILE%\.dsh\plugins\dsh-siri-bridge`
2. 按方式 B 改 `package.json`（`link:` 指向那个新位置，`bundles` 里加一条）
3. 按方式 B 的提示建好 junction
4. 重启 DSH，进设置页

**别直接把自己的整个 `~/.dsh` 发出去**，里面的会话、口令、配置都在；这个包只含插件代码，是干净的。

## 二、设置页长什么样

打开「设置 → 插件 → Siri 语音桥」，页面上有几块：

| 区块 | 干什么 |
|---|---|
| **服务状态** | 服务在不在跑、端口、本机地址；配置有问题会红字直接告诉你 |
| **① 打开开关** | 总开关。关着的时候一个端口都不开 |
| **② 选送进哪一间会话** | 手机上说的话落到哪个会话；选完可以点「发一句『在吗』试试」 |
| **③ 找地址** | 点「自动查找」列出这台电脑的地址，并**自动把【发送】那条复制到剪贴板**；「检查服务能不能连」会分别从本机和网卡各连一次，能区分「服务没起」和「防火墙拦了」 |
| **④ 手机快捷指令这么填** | 五步照抄，下面是【发送】【接收】两条现成 URL，点一下就复制 |
| **⑤ 出门还能不能用** | 没装 Tailscale 时提示只有局域网；装了会多一条 `100.x` 地址 |

页面底下还有「连不上怎么办」和最近 80 条日志。

## 三、手机上怎么配

两条搭配着用：**稳定版**是主力，推荐加桌面、从图标点开；**极速版**专门留给「嘿 Siri」呼出。

### 稳定版 · 推荐放桌面（语音 / 打字自己选，还能连着聊）

```
重复 10 次
    从包含「预热请求…」的菜单中选取
        文本
        语音
        文本                       ← 这行是「文本」两个字的文本块，不是动作的结果
        通过「想和小橙说什么?」请求 文本
        语音                       ← 这行是「语音」两个字的文本块
        听写文本
    结束菜单
    如果 菜单结果 是 听写的文本
        获取 [发送地址]/say?a=[听写的文本]
    否则
        获取 [发送地址]/say?a=[提供的输入]
    结束如果
    获取 [接收地址]/wait
    显示 [URL 的内容] 通知
结束重复
```

重点：

- 菜单里那两行「文本」「语音」是**文本块**（把这两个字拖进菜单当一项），不是动作的结果；
  选中「文本」就走「文本」那一支。
- 「文本」下面挂的是「请求 文本」动作（弹输入框让你打字），「语音」下面挂的是「听写文本」。
- 每个「获取」展开看：**方法写 GET**，头部不填、请求体不填；URL 那一栏贴设置页给的现成地址，
  后面的方括号是从变量列表里插进去的，别手打。
- 长按指令 → 分享 → 「添加到主屏幕」，以后从桌面图标点开。从图标启动时 Siri 不抢麦克风，
  选「文本」弹出的是输入框而不是自动语音，能老老实实打字。
- 每轮先弹一下菜单，等于按了个「我还在」，Siri 不会在你还没说完时自作主张接管；
  想不聊了，直接结束快捷指令就行。
- 判断条件保持原样就能用（见下面「小毛病」）。

**小毛病**：那句 `如果 菜单结果 是 听写的文本`，拿「菜单选的词」去比「听写出来的字」，
基本永远不相等，所以实际总走「否则」那一支。现在能跑通是因为两边都落到同一个发送口；
真想按来源分清，就改成 `如果 菜单结果 是 文本`，并在每支里把内容存进一个变量，后面统一拼进 `say?a=`。

### 极速版 · 留给 Siri 呼出（只说语音）

名字必须起成「使用deepseek」这种好念的，Siri 才叫得动（见下面「给它起个好叫的名字」）。

```
重复 10 次
    听写文本
    获取 [发送地址]/say?a=[听写的文本]
    获取 [接收地址]/wait
    显示 [URL 的内容] 通知
结束重复
```

「获取」同样展开确认：方法 **GET**，头部和请求体都不填。

适合：喊一句「嘿 Siri，使用deepseek」就直接用，不用掏手机点图标，纯语音。
代价：一轮说完，Siri 会等你几秒；**想下一句别想太久**，不然它就把你接下来的话当成在跟她说了。

### 放到桌面上用（重要）

1. 快捷指令 App 里，长按这条指令 → 分享 → 「添加到主屏幕」
2. 以后从桌面图标点它启动，不要从 Siri 唤起
3. 从桌面启动时，Siri 不会抢麦克风，选「文本」那一支就能正常打字输入了

从 Siri 直接唤起时，iOS 27 的 Siri 会自己判断要不要接管输入，经常把「请求文本」变成语音；
绕开它的办法就是走桌面图标。

### 给它起个好叫的名字（这条说的是极速版）

1. 快捷指令里点**极速版**这条右上角「⋯」→ 最上面那行名字，改成顺口的，比如「使用deepseek」
2. 名字别太长、别有生僻字，Siri 咬字才准；改完念一遍「嘿 Siri，使用deepseek」试试
3. Siri 只认名字调指令，名字对不上它就听不懂你在使唤谁；叫不动时先改成简短英文或拼音再试

两条指令**别起同一个名字**，Siri 会分不清该唤醒哪条。稳定版随便叫（比如「小橙」），
反正从桌面图标点开，Siri 不管它；桌面图标也跟着是这个名。

几条注意事项：

- 两条都用 **GET**，别填请求体、别填请求头。
- 发送那条后面**直接接**听写文本，不要加引号。
- 第 4 步用「**显示通知**」，不要用「显示提醒」——提醒会一直卡在那儿挡住后面的操作，通知弹一下就没。
- 想先验通道：把【测试】那条（`/ping`）丢进手机浏览器，看到 `pong` 就通了。
- 【接收】那条最长挂 120 秒，苹果「获取URL内容」大概 60 秒就断；断了重说一句就行，不会乱。

## 四、接口（想自己写客户端的话）

所有接口都是 GET。

| 路径 | 说明 |
|---|---|
| `/dsh-siri-bridge/say?a=一句话` | 把这句话送进选中的会话，立刻返回 `ok` |
| `/dsh-siri-bridge/wait` | 长轮询：等基线之后的下一条回复，超时返回「还在想」 |
| `/dsh-siri-bridge/reply` | 取最近一条回复（调试用） |
| `/dsh-siri-bridge/ping` | 健康检查，返回 `pong` |
| `/dsh-siri-bridge/state` | 设置页用的完整状态 |
| `/dsh-siri-bridge/probe` | 重新探一次网络，返回可用地址 |
| `/dsh-siri-bridge/selftest` | 本机 + 网卡各连一次，判断是不是防火墙的问题 |
| `/dsh-siri-bridge/test` | 往会话里发一句「在吗」 |

端口默认 **3919**，监听 `0.0.0.0`（局域网和 Tailscale 都连得上）。

如果设置里填了「口令」，上面每个请求后面要加 `&t=口令`。

## 五、原理（为什么它能工作）

插件在宿主里拿四样东西：

| 宿主能力 | 用途 |
|---|---|
| `agents` | `agent.followup({ role:'user', content:[{type:'text', text}], source:{ kind:'user' } })` 把话送进会话 |
| `sessions` | 列出能选的会话 |
| `sessionTitle` | 显示会话标题 |
| `webServer` | 挂设置页和上面那些接口 |

回复是监听会话事件流拿到的：`assistant/message` 事件里 `data.text` 就是正文；空字符串的那几条是**工具阶段的中间回合**，要跳过。

> 自己写的时候注意 `source.kind` 必须是 `'user'`。写成自定义的（比如 `'siri'`）事件会被静默吞掉——会话里能看到一条消息，但模型收不到，只会得到空回复。

## 六、常见问题

**设置页空白**
插件已经加载了，但界面没注册上。检查 `package.json` 里的 `dsh.client` 段是不是被删了或改坏了；改完重启 DSH。

**手机连不上，本机却能连**
Windows 防火墙拦了入站。放行 3919 端口（TCP 入站）即可。

**重启 DSH 之后手机又连不上了**
DSH 自己的网页端口每次都变，但这个插件的端口是固定的，不受影响。如果真连不上，多半是总开关被关了。

**出门在外连不上**
需要 Tailscale（电脑和手机登录同一个账号），然后回设置页点「自动查找」，把 `100.x` 那条换进快捷指令。

**电脑关机或休眠就断**
这是必然的——服务跑在这台电脑上。

## 七、卸载

1. 从 `package.json` 的 `dsh.bundles` 里删掉 `dsh-siri-bridge`，再从 `dependencies` 里删掉那一行；
2. 重启 DSH；
3. 删掉插件文件夹。

配置文件在 `~/.dsh/siri-bridge-config.json`，要清干净的话一起删。
